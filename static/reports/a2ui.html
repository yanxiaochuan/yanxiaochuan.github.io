🤖 A2UI: Agent to User Interface

由 Google 于 2025年12月开源的声明式 UI 协议，让 AI Agent 通过 JSON 消息"说出 UI"，客户端使用原生组件安全渲染——无需执行任意代码。

A2UI 是什么？

A2UI（Agent to User Interface）是一个声明式 UI 协议，专为 Agent 驱动的界面设计。它不是一个框架，而是一种协议/规范。

🛡️

安全优先 (Security First)

声明式数据格式，非可执行代码。Agent 只能使用客户端预审批的组件目录 (Catalog) 中的组件，杜绝 UI 注入攻击。

🧠

LLM 友好 (LLM-Friendly)

扁平化邻接表结构 (Adjacency List)，组件以 ID 引用。LLM 可逐条生成 JSONL，不需一次性输出完美嵌套 JSON。

🌍

跨平台 (Framework-Agnostic)

一份 Agent 响应全平台通用。同一 JSON 可渲染为 Angular / React / Flutter / SwiftUI / Jetpack Compose 原生组件。

⚡

流式渲染 (Progressive Rendering)

通过 JSONL/SSE 流式传输，用户实时看到界面逐步构建，无需等待完整响应，体验如同"看见 AI 在画 UI"。

🔗

传输无关 (Transport-Agnostic)

兼容 A2A 协议、AG-UI 协议、SSE、WebSocket 等任意传输方式。可无缝嵌入现有 Agent 架构。

🎨

原生体验 (Native Feel)

无 iframe。客户端使用自有 UI 框架渲染，继承应用的样式、无障碍和性能特性，Agent 生成的 UI 浑然一体。

解决什么问题？

传统 Agent 只能文本对话，效率低下。A2UI 让 Agent 生成丰富的交互界面。

❌ 传统文本交互 (Before)

  • 用户："帮我订明天7点的餐"
  • Agent："哪天？" → 用户："明天"
  • Agent："几点？" → 用户："7点"
  • Agent："几个人？" → 用户："2个"
  • 多轮对话、效率低、易出错

✅ A2UI 交互 (After)

  • Agent 直接生成一个订餐表单
  • 包含日期选择器 + 时间选择器
  • 人数滑块 + 确认按钮
  • 用户一步完成所有输入
  • 体验流畅、信息完整、无歧义

核心架构流程

👤 用户发消息
→
🤖 Agent 生成 A2UI JSON
→
📡 SSE/A2A 流式传输
→
📱 客户端原生渲染
📌 关键定位：A2UI ≠ 框架，≠ HTML 替代品，≠ 仅限 Web。它是一个协议，就像 HTML 是浏览器的 UI 协议一样，A2UI 是 Agent 的 UI 协议。

四种核心消息类型

服务端通过 JSONL 流向客户端发送以下四种消息：

消息类型作用说明
surfaceUpdate定义/更新 UI 组件包含扁平化组件列表，用 ID 引用构建树
dataModelUpdate更新数据模型与 UI 结构解耦，可独立更新数据无需重发 UI
beginRendering触发渲染信号指定 root 组件 ID 和 Catalog，防止闪烁
deleteSurface删除 UI 区域清除指定 Surface 及其所有内容

完整流式协议示例 (Profile Card)

JSONL Stream 
// 1. 逐条发送组件定义
{"surfaceUpdate": {"components": [{"id": "root", "component": {"Column": {"children": {"explicitList": ["card"]}}}}]}}
{"surfaceUpdate": {"components": [{"id": "card", "component": {"Card": {"child": "card_body"}}}]}}
{"surfaceUpdate": {"components": [{"id": "card_body", "component": {"Column": {"children": {"explicitList": ["title", "desc"]}}}}]}}
{"surfaceUpdate": {"components": [{"id": "title", "component": {"Text": {"text": {"literalString": "Hello A2UI"}, "usageHint": "h2"}}}]}}
{"surfaceUpdate": {"components": [{"id": "desc", "component": {"Text": {"text": {"literalString": "Agent 生成的 UI"}}}}]}}

// 2. 发送数据模型 (可选)
{"dataModelUpdate": {"contents": {}}}

// 3. 触发渲染
{"beginRendering": {"root": "root"}}

三层解耦架构

🏗️

组件树 (Component Tree)

由 surfaceUpdate 定义的抽象组件树结构。扁平化邻接表，通过 ID 引用描述父子关系。

📦

数据模型 (Data Model)

由 dataModelUpdate 管理的 JSON 状态。组件通过 Data Binding (BoundValue) 绑定到数据路径。

🎨

组件注册表 (Widget Catalog)

客户端定义的映射表：抽象组件名 → 原生实现。每个平台有自己的 Catalog 实现。

数据绑定 (BoundValue)

组件属性支持三种绑定模式：

Data Binding 
// 1. 字面量：静态值
"text": { "literalString": "Hello" }

// 2. 数据路径：动态值，从 dataModel 解析
"text": { "path": "/user/name" }

// 3. 双重绑定：初始化默认值 + 绑定路径
"text": { "path": "/user/name", "literalString": "Guest" }

v0.8 vs v0.9 语法对比

v0.9 大幅简化了组件语法：

v0.8 (Stable) — 嵌套结构

{
  "id": "title",
  "component": {
    "Text": {
      "text": {
        "literalString": "Hello"
      },
      "usageHint": "h1"
    }
  }
}

v0.9 (Draft) — 扁平结构

{
  "id": "title",
  "component": "Text",
  "text": "Hello",
  "variant": "h1"
}

邻接表模型示意

组件以扁平列表传输，通过 ID 引用构建树：

Adjacency List → Tree 
// 扁平化传输（邻接表）
[
  { id: "root",  type: Column, children: ["card"] },
  { id: "card",  type: Card,   child: "body" },
  { id: "body",  type: Column, children: ["title", "btn"] },
  { id: "title", type: Text,   text: "Hello" },
  { id: "btn",   type: Button, child: "btn_t" },
  { id: "btn_t", type: Text,   text: "Click" },
]

// 客户端重建的树结构：
Column (root)
  └─ Card
       └─ Column (body)
            ├─ Text: "Hello"
            └─ Button
                 └─ Text: "Click"

协作关系

🔗 A2UI + A2A + AG-UI = 完整的 Agent UI 栈
A2A（Agent-to-Agent）负责 Agent 间通信；AG-UI 负责 Agent 与前端的实时通信；A2UI 负责描述 UI 内容。三者互补而非竞争。
